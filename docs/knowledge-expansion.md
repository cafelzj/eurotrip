## 内容维护约定

- 新专题放在 `data/knowledge-cards.js` 的 `knowledgeCards`，关联放在同文件的 `knowledgeRelations`；文件只含 JSON 常量。既有人物仍使用原 ID 和原文件，避免新建重复的人物卡。
- 保留现有“当地人物”“历史 / 地理 / 趣闻”二级分类，副标题补充主题线索；不增加分类详情页或新的交互模式。
- 归属依据具体内容和人物经历。国家通史、跨城主题可明确关联多个国家或城市；县级内容同时关联上级城市时，以正文说明行政和文化尺度。
- 每张新卡提供至少两个有意义的阅读方向，例如历史 → 人物、人物 → 场馆、同主题跨城比较。双向关系只负责知识导航，不继承地点坐标。
- 新知识卡均不附 POI。地点仍由已有地点卡承担，因此完整地图与随身地图的地点来源保持一致。
- 使用具体年代区分事件、建造、修缮和后世纪念；非物质文化遗产与世界遗产地点分别说明，文学、传说与历史材料分别表述。

## 来源与更新

延伸阅读优先使用 UNESCO 项目页、博物馆、档案、大学、科学机构、地方政府与专业词典；部分链接为机构入口，部分为具体专题。另有百科传记帮助定位人物和年代。

本轮为静态知识整理，来源链接不代表逐页完成联网核验，也未填写“已核验”或来源访问日期。整理日期仅记录内容更新。票价、营业、入境等变化较快的资料仍由原有实用卡与官方入口负责，来源分级、逐页核验和失效检查继续列入“方案”的待办。

瀑布流继续对当前匹配的真实卡片分批加载；本轮扩充资料库，没有接入实时模型生成或循环复制卡片。
