# 目录与维护流程

项目保持浏览器直接加载的静态网站，不增加网站构建步骤。

```text
index.html、根目录 JS/CSS   网站入口与展示逻辑
data/                     浏览器加载的正式数据
  snapshots/              网站提供下载的三份 Eurostat 原始数据
assets/                   展示图片、地图、图片署名与许可
vendor/                   第三方库及许可
docs/                     当前使用与维护说明
research/                 来源、检索、候选、审核、历史批次
  flavors/reading-notes/   有来源指纹的编辑阅读摘记
  archives/               原始材料的归档清单
  .local/                 本地原件与完整响应，Git 忽略
scripts/                  可复用的维护、生成与检查工具
tests/                    数据与浏览器检查及辅助脚本
work/                     未来临时工作区，Git 忽略
```

## 正式数据与研究记录

`data/` 顶层30个JS均由入口加载。是否用于展示应从 `index.html` 和运行时代码确认，不能由后缀、文件大小或名称判断。数据字段中的图片署名、许可、来源、审核状态属于展示及追溯所需内容，不因研究目录已存一份就随意移除。

`research/` 里的当前来源记录可以维护；按日期保存的批次说明保留当时状态，旧数字不改写成今天数字。阅读摘记与原始网页不是同一种材料：笔记可公开整理，完整网页和工具响应只作本地保存，是否另行公开须核对来源许可。

迁移路径见 [path-migrations.json](../research/path-migrations.json)。本次移动67个研究文件，48份阅读摘记保留原字节；网站代码、卡片ID、图片及三份公开统计下载的路径保持原位。历史JSON改为新路径后，其仓库链接和脚本引用同步更新；旧路径可结合迁移表与Git历史追溯，不保留第二份可编辑副本。

## 维护顺序

资料内容的固定流程是：**搜索资料 → 保存搜索结果与阅读底稿 → 核实或判断合理性 → 纳入网页 → 检查与发布**。这不是可省略的临时步骤，后续内容维护遵循根目录 `AGENTS.md`。

- **来源直接支持**：按来源实际支持的范围陈述，保留出处，不把名称与地域核对扩展成配方、历史、经营现状均已验证。
- **有依据的合理判断**：可以纳入网页，明确写出判断依据和不确定性，与已核实事实区分。
- **待核线索**：保存候选、证据缺口及链接；如收录到网页，显著标注待核，不能伪装成确认事实。
- **未采用内容**：保留理由，便于未来复核，避免重复搜索或重复采用已否决材料。

采用记录应能从条目追溯到来源与底稿，底稿也能看出采用、待核或否决结果。保存资料与更新网页两步都要落实。

1. 在研究目录记录检索词、来源网址、读取日期、证据范围和候选状态；完整响应写入 `.local/`，公开索引记录指纹。网络错误和零结果也保留。
2. 核对后编辑正式数据，保留稳定ID；不要直接把候选表当作正式数据重新导入。
3. 由生成脚本维护的文件通过对应脚本更新，生成前确认输入来源与版本，避免联网运行脚本意外覆盖已编辑数据。具体关系见 [数据索引](../data/README.md)。
4. 更新派生统计与研究条目引用，执行 `python scripts/check-research.py` 和受影响检查；有本地归档时再加 `--local-archives`。
5. 换环境前另外保存 `.local/archives/` 的归档包。Git中的清单和公开底稿不能代替未公开的原始材料。

## 临时文件与后续整理

`.gitignore` 只排除Python缓存、测试输出、依赖、本地研究原件和工作区，没有忽略JSON、HTML、图片等整类资料。

根目录JS/CSS、图片格式和缩略图本轮保留。后续如迁入专门的代码目录，需要一起调整入口顺序、测试硬编码、CSS资源相对路径、图片配置及旧链接；不能仅移动文件。图片是否删除须核对实际 `src`、缩略图、格式回退、署名和审核记录，不能按同名或扩展名直接清理。
