# 漫游词典 · Eurotrip

面向匈牙利、奥地利和德国旅行的中文词汇学习网站。词条按中文、英语、匈牙利语、德语排列，覆盖八个生活场景，支持跨语言搜索、浏览器本地收藏、设备语音朗读和词条详情。

## 本地运行

无需安装依赖，使用 Python 3：

```sh
cd /workspace/eurotrip
python3 -m http.server 3000 --bind 0.0.0.0
```

打开网站即可使用。主词库与彩色图示保存在本地；外部字体不可用时自动使用系统字体。词典链接需要联网。语音支持取决于设备及浏览器的语言包，收藏保存在当前浏览器。

## 文件

- `index.html`：页面和详情对话框
- `style.css`：桌面与手机布局
- `data.js`：多语言词库及已收录的词源说明
- `app.js`：分类、搜索、收藏和朗读

词源未收录的词条明确标注，并提供 Wiktionary 查阅入口。图像是辅助记忆图示而非实物照片。尚未接入真人录音或后台账户。

## 国家与城市指南

默认首页现在是国家概览，覆盖匈牙利（布达佩斯、德布勒森、塞格德）、奥地利（维也纳、萨尔茨堡、因斯布鲁克）、德国（柏林、慕尼黑、汉堡、科隆），共 10 座城市、30 处地标。

- `#guide/hu`、`#guide/at`、`#guide/de`：国家概览
- `#guide/hu/budapest`：城市详情，可直接分享
- `#words`：原有多语言词典
- `guide-data.js`：概览、坐标、城市简介、特色、名人及交通/旅游链接
- `guide.js`、`guide.css`：旅行指南交互与响应式布局
- `borders.js`：Natural Earth 110m 国界，公有领域，来源 https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_110m_admin_0_countries.geojson
- `vendor/leaflet`：Leaflet 1.9.4，BSD-2-Clause，许可证随文件保存；安装时校验 npm registry 的 SHA-512 integrity

地图底图采用 OpenStreetMap 标准瓦片并显示署名，只在当前视图请求，不预抓取或缓存大量瓦片。需联网；失败时保留本地国界与坐标标记，并提示外部地图入口。景点坐标用于位置概览，不保证为实际入口。大范围国家概览不作为精确边界参考。

交通图优先链接官方线路图页面；德布勒森、塞格德、萨尔茨堡、因斯布鲁克、科隆目前提供运营商网站的线路图查询入口，尚非已核验的直接 PDF。交通 App 链接指向官方/提供方说明网站；menetrend.app 是第三方。当前云网络无法访问这些运营商网站，因此未逐项验证外链可达性；票价、开放时间、实时线路均需在官方站点确认。

## 分层城市探索与即时 POI

城市介绍新增四个栏目：当地美食、超市品牌、机场/火车站、热门商圈。`poi-data.js` 收录 10 城的美食概览与 46 个精选交通/商业地点；`poi.js` 实现父图层、子图层独立开关，以及按城市保存在浏览器中的显示偏好。食品简介不表示附近每一家餐馆都供应这些菜。

实时地点来自 OpenStreetMap Overpass，浏览器直接 POST 至 `https://overpass-api.de/api/interpreter`，无需密钥。节点和面状地点（center）均可显示。超市别名归并如 INTERSPAR→SPAR、ALDI Süd/Nord→ALDI；奥地利 HOFER 单列。品牌清单为分类，不能据此断言某城有该品牌门店。

为控制全城门店数量和公共接口负荷：

- 默认只显示精选景点；勾选栏目后查询当前视野，或点击“搜索当前地图范围”。
- 查询必须 zoom≥13，视野宽、高各不超过15km；移动地图默认不联网，用户可启用900ms防抖的自动搜索。
- 查询输出最多601条以判断截断，实际保留最多600条；达到上限明确提示结果不完整，建议缩小范围。
- 查询范围/类别完全相同时使用10分钟内存缓存，最多24组；图层开关650ms防抖、只保留一个活动请求，切城市销毁并取消请求。
- 使用本地 Leaflet.MarkerCluster 1.5.3（MIT）聚合；最多显示离地图中心最近的30个列表条目，地图仍显示全部已载入且启用的地点。最大缩放下可展开重叠点。
- 请求失败、限流、超时/Overpass remark 不视为“没有门店”；保留已有数据并明确标识范围尚未更新，提供外部地图搜索入口。空成功结果也不保证现实中没有地点。

瓦片和Overpass接口需联网与跨域支持。当前云代理尚未放行新的服务域名，实网查询暂未验证；域名及更新后的启动说明已存环境草稿。公共网站的请求来自访问者浏览器，不依赖云容器代理。OSM数据可能缺少名称/地址、过时或不完整；营业时间标签不等于实时营业状态。

`node tests/poi.cjs` 使用受控的Overpass响应检验品牌筛选、不同栏目共存、点聚合、范围保护、缓存、服务器限流/超时、600条截断、POI弹窗、手机布局及切城隔离。模拟测试不代表真实Overpass服务已连通。

## 景点分类、城市环境与美食比较

现有 10 城共 50 个精选景点，按教堂、博物馆/美术馆/展览、大学、地标建筑、公园/其他分类。城市页支持各类别独立控制地图与卡片显示，筛选偏好按城市保存。大学坐标代表标注的主楼或校区区域，不代表大学所有设施；综合建筑群使用一个主要分类。

每个城市新增河流与地形、概括性季节气候、货币、相对物价描述。气候不是即时预报，价格不是实时报价，不能用作固定预算或天气保证。

每城提供 6 条美食介绍，共 60 条城市美食记录（含跨城常见食品，非 60 种独有美食），可展开“当地美食”按类型过滤，查看口味/做法/同类食物比较。图片链接是 Wikimedia Commons 的图片搜索入口，不是指定餐馆照片；未逐项验证外部图片搜索结果。饮食限制须与店员确认。`node tests/city-details.cjs` 验证分类同步、偏好保存、河流/货币、价格提示、美食筛选和图片链接结构。

## 容易忽略的小事

`travel-tips.js` 含30条提醒：2条三国通用、每国6条、每城1条。国家页组合8条，城市页组合9条并优先展开本城提醒；可按支付、交通、购物、餐饮、日常过滤，卡片可独立展开。覆盖本币结算、卡种差异、票区/验证、机场交通、周日购物、瓶罐押金、点水与账单等。

内容是稳定规则的概括与操作建议，不提供实时价格、营业状态或班次。部分规则有票种、线路、门店、地区、日期例外；来源链接有官方专题和首页入口，未逐项验证外链实时可达性。BKK链接只适用于布达佩斯，并非匈牙利其他城市的通用票务规则。

启动服务后运行 `SITE_URL=http://127.0.0.1:3002 node tests/travel-tips.cjs`，验证国别/城市内容、筛选、展开、来源链接结构、手机布局及词典兼容。

## 国家知识子专区

国家页包含五个独立面板：跟着地图探索（默认）、冷知识、必备信息、美食、本地特产。内容位于 `country-knowledge.js`；支持页内标签、方向键/Home/End、浏览器历史和直达URL，例如 `#guide/hu?zone=facts`、`#guide/at?zone=food`、`#guide/de?zone=specialties`。切换国家保留所选专区；城市仍使用原有 `#guide/hu/budapest` 路径。

每国4条冷知识、6条关联城市的美食、4类有产地说明的特产。必备信息整合原有8条提醒与语言/货币/求助信息。隐藏地图面板时销毁地图，返回地图时重新初始化，防止隐藏容器尺寸或事件残留问题。国家美食与特产引用Commons图片搜索，不是商品推荐或特定商店照片；城市关联不主张独家起源，特产产地可位于尚未收录的地区。

启动本地服务后 `SITE_URL=http://127.0.0.1:3003 node tests/country-zones.cjs` 验证15个国别专区、标签与历史、键盘/手机操作、提醒和城市跳转。原测试已按新国家页面入口调整。

## 卡片漫游与关联网络

新增 `#cards` 目录及 `#card/<id>` 独立详情，支持类型筛选、中外文搜索、分页、可分享链接、浏览器返回和最近浏览。初始350张卡片：国家3、城市10、美食60、地点103（50景点+46交通/商业地点+7餐饮/市场示例）、地图10、人物23、冷知识12、特产12、提醒30、词汇87。美食是城市记录，并非60种互不重复的菜；人物含“洪堡兄弟”这一组人物主题。

- `people-data.js`：人物简介、别名、生平/作品关联城市和资料来源；7个餐饮/市场探索示例。
- `card-graph.js`：稳定ID、卡片目录、显式双向关联、关系标签、详情、来源与安全文本引用。
- `cards.css`：卡片目录、详情、关联卡片和地图专注视图。
- `#map/vienna?food=food-vienna-1`：美食地图，显示相关场所与附近餐饮查询。
- `#map/salzburg?focus=place-salzburg-1`：在站内地图定位地标。
- `#card/person-mozart`：人物→城市/纪念馆/冷知识/以人物命名的甜品。

国家、城市、食物、地点、人物、冷知识、特产、提醒和词汇通过同一目录连接；关系标签区分生平、设计作品、收藏、名称纪念、市场探索等，不把邻近餐馆当作指定菜品的供应保证，也不把纪念名称解释为本人发明。图库与外部资料链接非逐项实网验证，部分仅为官方入口。新餐饮示例不是商业推荐或即时菜单。

即时OSM地点可进入独立卡片并返回地图：打开过的最近20张仅在本浏览器sessionStorage保留，跨设备或会话可能无法恢复，缺失时提供重新探索提示；内存最多900个即时地点，并移除过期卡片的反向关联。目录每次展示48张，关联分组超过6条时可展开剩余。浏览记录仅存当前浏览器会话。

`SITE_URL=http://127.0.0.1:3004 node tests/card-paths.cjs` 验证关联完整性与双向性、人物→地点→地图、美食→场所→地图、冷知识内嵌引用、即时POI会话恢复、词汇弹窗跳转、目录搜索分页、手机及未知卡片回退。即时服务使用受控响应；不表示Overpass实网已连通。原国家、城市及POI回归检查亦已执行。

修正原因斯布鲁克人物介绍：安娜·法伊特出生地并非因斯布鲁克，改为关联贝吉瑟尔跳台的设计者扎哈·哈迪德。

从美食地图打开即时餐饮卡片时，会双向保留“从这道风味开始探索/探索过的附近餐饮”这一浏览上下文。该关系只说明探索路径，明确不保证菜单或供应；它与有编辑依据的餐饮示例关系采用不同标签。

## 企业 / 品牌与日常食品

现为11类、410张初始卡片：增加37个企业/品牌、21款日常食品饮料及2个公众品牌场所（总景点52处、地点105张、美食81张）。`brand-data.js` 收录资料并添加品牌场所及国家“企业 / 品牌”第六专区；`brands.css` 提供版式。食品在国家美食、特产及城市折叠栏目中复用同一卡片，不重复登记。

品牌卡区分产业企业和消费品牌，说明起源、总部/历史地理联系及跨国品牌情况。重要例子：BMW的慕尼黑、MOL的布达佩斯；SAP在瓦尔多夫而非任意已收录城市；HOFER属ALDI Süd，ALDI Nord与Süd不混为同一总部；SPAR Österreich企业与荷兰起源的SPAR国际品牌体系不同；Milka为德国市场常见的瑞士起源跨国品牌。企业归属与地理关系需以对应最新官网为准，官方外链未逐项验证可达性。此目录不是规模、销量、喜爱度或商业推荐排名。

日常食品包括Túró Rudi、Sport/ Balaton、瓶装水、HELL、Márka、Erős Pista、Manner、Almdudler、Red Bull、RAUCH、PEZ、Kelly’s、HARIBO、Ritter Sport、LEIBNIZ、funny-frisch、fritz-kola、Club-Mate、BIONADE和Milka。说明口味比较、普通购买渠道、单价比较与保存要求，不提供实时价格或库存。Túró Rudi明确为冷藏食品，不当作常温伴手礼。

商品卡以`food-product-<id>`登记并设置`shopping:true`，地图以附近超市为查询目标，区别于餐馆查询。可选同一国家内已收录城市查店，城市只作购买探索起点，不是产地或库存声明。打开实时超市卡片后保留商品来源及Lidl/ALDI/HOFER/SPAR品牌标识关系（不保证具体运营主体、特许关系或货品）。跨会话恢复沿用既有即时卡片限制。

品牌公众场所与办公室分开；MOL Campus、BMW Welt开放与预约查官网，不自动开放总部或工厂。城市初始地图聚焦城区（至少13级），远端场所可通过卡片定位或“显示全部标记”查看，避免新增远点把默认POI查询范围拉得过大。
