# 漫游词典 · Eurotrip

面向欧洲旅行与中国城市探索的中文网站：欧洲国家、中国城市、物产图谱、关联卡片与分层地图，以及中文 → 英语 → 匈牙利语 → 德语的旅行词典。

公开网址：https://cafelzj.github.io/eurotrip/

## 本地运行

纯静态 HTML、CSS、JavaScript，无需安装应用依赖：

```sh
cd /workspace/eurotrip
python3 -m http.server 3014 --bind 0.0.0.0
```

浏览器访问站点即可使用。地图底图、即时门店查询、官方资料及词典外链需要联网；设备朗读取决于系统语言包。收藏与地图偏好保存在当前浏览器。

## 页面与卡片约定

顶部按「欧洲国家」「中国城市」「旅行词典」「物产（beta）」排序。「欧洲国家」收录匈牙利、奥地利、德国、塞尔维亚及十三座城市；「中国城市」包含江苏省的苏州、徐州、无锡三个地级市，并按「省份 → 地级市 → 全市概览或县 / 县级市」选择目的地。三市下辖的 11 个县、县级市均有基础卡片；沿用目的地标题、五个一级分类、二级分类、卡片与地图交互，不展示中国国家概览。两组菜单、最近浏览目的地与内容范围独立。

旅行词典的「展示语言」可勾选要看的语言，默认保持中文、英语、匈牙利语、德语顺序；新增塞尔维亚语（拉丁字母）作为可选语言。设置保存在浏览器，列表、详情、词典链接和感谢语朗读同步更新；至少保留一门，支持恢复默认。搜索覆盖所有已收录语言。新增语言只需在 `data/languages.js` 注册元数据，并在词条补充同名字段；缺少翻译时显示未收录且不生成朗读按钮，不在视图里写死四列。词条索引保持不变，收藏无需迁移。窄屏采用带语言标签的词卡。

塞尔维亚收录贝尔格莱德、诺维萨德、尼什三座城市，新增73张卡片，沿用五类主题与单点 / 动态搜索 / 无坐标规则。共同出现的Lidl与dm复用原品牌卡片，城市关联不代表起源或总部；本地零食、食品及品牌与购物、人物、场所建立双向链接。票务、入境、住宿登记与运行安排提供官方查询入口，页面不保证票价、签证政策或门店库存实时有效。塞尔维亚参考轮廓沿用Natural Earth 1:110m数据，仅用于浏览。

欧洲国家菜单和中国城市菜单末尾分别提供「卡片管理」（`#card-manager`、`#card-manager/china`）。两个管理表分别查看对应范围的静态卡片，国家与城市筛选、搜索、分页、CSV 导出及筛选记忆互相独立；每张卡片在同一管理表只出现一行，多归属卡片按明确归属进入相应范围；支持国家、城市、一级分类、二级分类组合筛选，按名称、副标题 / 当地名称、归属、分类、简介、完整详情与来源全文搜索，多个关键词可跨字段匹配。支持分页、URL恢复筛选、展开原文和来源、返回详情、地图入口及导出全部筛选结果CSV；动态搜索产生的临时门店不混入静态管理表。

「景点与建筑」新增「世界遗产」二级分类，独立数据文件收录14个UNESCO正式列名条目及官方入口。历史城区和跨国区域的范围分别说明，图钉仅为单个参考锚点；未明确属于已收录城市的遗产保持国家归属，不按邻近关系分配城市。费尔特湖／新锡德尔湖文化景观使用同一张卡片关联匈牙利、奥地利。

卡片归属由`CardStore.countryIds / cityIds`统一读取：单值`country / city`与数组`countries / cities`取并集去重，城市也补足其所属国家；`city`在带POI的卡片中同时保留为具体地点的城市锚点。一个卡片ID可同时出现在多个国家和城市集合，管理表和详情完整展示归属，不复制卡片，也不增加POI数量。副标题可用`subtitle`，当地名称用`local`，二者均可搜索。

五个**卡片一级分类**：🚆 交通出行、🍽️ 美食与特产、🛍️ 购物、🏛️ 景点与建筑、💡 冷知识与人物。交通 App、线路图、买票、机场、火车站和轮渡码头归入交通出行；支付/货币与购物提醒归入购物；点餐、结账和饮用水提醒归入美食与特产。医药服务归入购物；「日常 / 应急」归入冷知识与人物，不再设置必备信息一级分类。交通出行新增「地铁」「共享单车 / 滑板车」，地铁按实际城市收录，共享骑行提供各国使用提醒与官方入口。每类下按**卡片二级分类**分组，例如乘车指南、机场、咖啡、超市、剧院。买票、乘车提醒、交通App与线路图统一归入「乘车指南」，保留`tickets` ID，旧名称与`transit-tools`筛选链接转入合并后的分类。博物馆、美术馆与展览馆统一归入「博物馆 / 美术馆 / 展览馆」；「公园 / 游乐园」收录大森林公园、英国花园及普拉特游乐园，温泉与山地起点另归「其他景点」。「连锁餐饮」同时展示连锁品牌和具体门店，地图行为仍分别为动态搜索与单点定位；「美食」与「甜品」分开展示。一级分类有简介，二级分类有专门总结；分类只有筛选与展开，不设置详情页。

二级分类独立展开，每组先显示三张，可继续加载。支持关键词、一级分类和二级分类组合筛选，URL 保留筛选状态。城市只展示明确关联的内容，并保留标明适用范围的全国/通用实用提醒。中国地级市的全市概览汇总本级与下辖县级目的地卡片；县级页面只显示本地卡片，不默认继承地级市的地铁或市区票务说明。

仅保留可在欧洲国家或中国城市集合中找到的独立卡片详情，当前卡片数量以数据目录为准。国家、城市与地图使用各自的指南/地图路由，不再创建重复卡片；词汇继续使用按展示语言配置生成的详情对话框。卡片之间保留有明确意义的双向知识关联和官方来源，但知识关联不推导地图坐标。旧的卡片漫游与分类详情渲染代码已删除。

每张卡片详情均有「ChatGPT 生成介绍」按钮，在新标签页打开 ChatGPT，并通过 `q` 参数带入当前卡片的公开名称、类型、所在地、简介、补充说明、少量知识关联与参考入口。默认请求约 800 字的中文介绍，针对地点、美食、人物、品牌等使用不同的介绍要求；不把已有卡片或模板文字伪装成现场生成的文章。实际生成在 ChatGPT 进行，是否登录及服务可用性由 ChatGPT 决定。无需模型后端或前端 API 密钥。另可复制提示词到其他模型；剪贴板不可用时提供可选中的文本。不会包含收藏、浏览历史或未公开凭据。

每张卡片只有以下一种地图行为，由 `KnowledgeHub.mapBinding` 集中判定：

| 行为 | 数据与交互 |
| --- | --- |
| 无地点 | 没有地图定位按钮；相关人物、菜肴、趣闻不会继承关联场所的坐标 |
| 一个固定 POI | 卡片自身的一个 `point`；卡片编号与唯一大头针对应，可双向定位 |
| 动态搜索 | 无固定坐标的超市品牌、连锁餐饮品牌或购买线索；进入地图后按范围搜索 |

连锁品牌用于搜索；搜索结果先登记为具体门店卡片，每张结果卡片只有一个固定位置。品牌与多家门店之间是知识关联，不代表品牌卡片关联多个固定 POI。餐馆、博物馆、教堂、剧院、大学、机场、车站、轮渡码头等具体场所均采用单个参考位置。

## 物产 · 德国、奥地利与匈牙利

三国共用国家选择、产区导读、食材、供需、能源与来源布局。德国和奥地利各62项食材，匈牙利60项；每国6个产区。仍按谷物（主粮）、水果、蔬菜与豆类、肉类、水产、油料与食用油、香料与调味、奶与乳制品、蛋类、坚果与籽实、糖料与蜂蜜、饮品与水十二类展示。支持中文、当地语言、英语、产区、季节、做法与特色筛选。德国区分本国海岸与进口海产；奥地利和匈牙利区分淡水生产与外部海产。准确emoji与文字标识、地方特色、做法、美食和既有卡片链接保留在食材内。

产区、菜式和收获月份为编辑导读，不作为每批商品的原产地证明或官方逐产区收获日历。标记“已读”的Eurostat农作物、乳品、葡萄园和水产养殖文章有读取日期与哈希；未逐页核验的官方旅游、水务入口另行标注。国家数字不按人口分摊给城市，食用可供量不改名为实际摄入。

每国53个产品/统计组的2010–2023同版FAO食物平衡表，显示产量、进口、出口、国内供给、食用可供总量（千吨）与同版Food÷人口的估算人均量（千克/人/年）。部分产品另有2020–2024新版农业产量与公布的人均可供量，年份、商品和单位分别标明，不拼成同年平衡。奥地利稻米农业单项在所读版本中没有国家序列，保持缺失，不当作零。

图表支持单产品多指标、多产品同指标，以及德国/奥地利/匈牙利同产品同指标对比。可选原值或共同正值基年100指数，支持逐年读数、原值表、SVG、完整JSON与CSV导出；三国对比SVG包含每条曲线的国家范围与对应来源。切换国家重建当前视图，返回物产恢复最近国家。

完整FBS和人口来自FixOurFood / AgriFoodPy固定提交 `3251e9fe9a8fb24a471e13c98f058f897c1f0135`，核对国家代码德国79、奥地利11、匈牙利97、2010–2023时间轴、千吨与人口单位。副本把缺失填为0，因此保守处理成未确认，不能当真实零。国内供给负值保留并标注；奶品折算、鱼类活重、籽粒与成品油等不按等重混算。2023小麦“产量/进口/出口/Food”（千吨）校验锚点：德国21536/11472/12694/6360；奥地利1745/2018/1365/854；匈牙利5942/816/3476/1284。

最新单项与能源净进口比例取自OWID公开镜像固定提交 `d3f4efb3873ab6ebd5624d66b66d401ab63abb79` 的31个FAO/WDI变量，保留元数据、上游机构和SHA-256。发电结构、净电力进口与燃料消费取自固定OWID Energy Data/Codebook，上游包含Ember及Energy Institute。显式报告的能源零值保留，不能套用FBS零值规则；净出口保留负号。2024发电结构与燃料消费、2025最新电力各标年份，不外推缺失的2025燃料消费。

新增实际读取的Eurostat 2024 `nrg_cb_e`、`nrg_cb_gas`、`nrg_cb_oil`：电力以GWh、天然气以TJ总热值、石油与石油产品（不含生物燃料部分）以千吨报告进出口，并列出可用的生产、内陆/最终消费原值。三份原始JSON-stat响应保存于 `data/snapshots/`，来源详情可直接下载，并按字节校验SHA-256。天然气EXP在所读版本中明确报0，页面保留值并说明这不是所有过境或市场毛流量结论，不据此计算进口依赖率。Eurostat毛发电与OWID/Ember不同口径独立展示，不强行拼平衡。

## 地图与动态门店

右下角「随身地图」默认收起，展开时初始化，收起时销毁；桌面默认宽 460px、画布高 340px，可继续放大。五个一级分类分别作为图层，名称、图标、颜色和编号前缀共用分类配置。每个固定 POI 使用对应卡片的名称、编号、图标、简介和详情链接，不沿关联卡片展开多个点；无地点的详情不会显示虚构大头针。国家和城市模式都提供「打开地图页面」入口。词典与完整地图页隐藏随身地图。

地图支持鼠标滚轮、触摸板滚动/捏合，以及触屏双指缩放；滚轮使用四分之一级步进和较低灵敏度，地图外仍可正常滚动页面。

完整地图共用国家/城市渲染器，内容与分类只来自当前目的地卡片。图层面板改为「一级分类 → 二级分类 → 卡片」的三层树。箭头独立展开/收起，复选框控制显示；父级按子卡片计算全选、取消和半选，不再叠加三套过滤状态。卡片叶子显示名称、编号及详情入口，点击地点定位并高亮树中对应项；动态品牌叶子注明「动态搜索」，勾选后按范围查询，点击名称可直接选择该品牌搜索。桌面左侧树形面板、右侧地图，手机上下排列。动态结果不追加到树中，继续在地图聚合与结果列表展示，品牌叶子提示已载入数量。共享品牌在详情和地图跳转时保留当前国家/城市语境，不把经营市场当成品牌起源或总部。

默认不请求外部门店。开启动态搜索后，移动地图经 900ms 防抖查询；可关闭自动搜索，也可手动查询或取消。浏览器直接 POST 到 `https://overpass-api.de/api/interpreter`，不需要密钥，只查询已收录品牌，响应再次检查品牌身份。

- 缩放至少 13，视野宽、高各不超过 15km；国家地图需先放大到城区。
- 每次最多保留 200 个门店，列表最多显示离中心最近的 30 个；地图使用 MarkerCluster 聚合。
- 品牌/name/operator 合并匹配；相同在途请求去重。范围按 0.005 度外扩对齐，缓存 10 分钟，内存最多 24 项、当前会话最多保存 8 项。
- 服务端计算超时 8 秒，客户端最多等待 10 秒，显示耗时并可取消。失败后自动搜索冷却 15 秒，手动重试仍可用；已有结果保留。
- 地点卡片的独立显示偏好按国家/城市保存，并兼容迁移原有分类开关；动态品牌每次进入默认关闭，明确的搜索深链接除外。
- 即时卡片最多 900 张；打开过的最近 20 张保存到 sessionStorage。国家范围搜索不擅自给结果分配城市。

中国城市与欧洲地图均使用 OpenStreetMap，由 `map-provider.js` 和 `data/map-providers.js` 集中管理。目的地通过 `mapProvider` 选择已接入的提供方；静态地点以 WGS84 存储，中国地点显式标记 `coordSystem`。后续接入高德时，需要增加合法的地图服务配置、渲染适配与 WGS84 → GCJ-02 转换，不能只替换瓦片地址；卡片内容、分类和地点 ID 可以继续复用。

底图为 OpenStreetMap 标准瓦片，保留署名；不预抓取。底图失败仍可显示本地国界与卡片坐标。坐标为位置参考，不保证入口、营业、菜单或库存；OSM 可能过时或缺失。

## 数据与代码结构

所有静态内容集中在 `data/`，文件只包含 JSON 形式的常量声明，不操作页面、调用网络或注册卡片。不引入数据库、框架或构建步骤，浏览器按顺序直接加载。

| 文件 | 维护内容 |

静态卡片统一使用明确的 `category` 和 `subcategory` ID，不通过名称关键词猜分类。卡片 ID 保持稳定；调整文件顺序不会改变 ID 或关联。新增静态内容只需编辑相应数据文件，列表、小地图和完整地图读取同一份卡片。

```js

  "id": "tip-vienna-ticket-choice",
  "type": "tip",
  "country": "at",
  "city": "vienna",
  "category": "transport",
  "subcategory": "tickets",
  "name": "维也纳：单次、多日票与月票怎么选",
  "description": "……",
  "note": "……",
  "sources": [["https://www.wienerlinien.at/web/wl-en/tickets", "官方票务入口"]]

```

`point` 与 `searchKind` 二选一，也可以都不填。固定地点使用 `point: {lat, lon, …}`；动态超市使用 `searchKind: "supermarket"`，连锁餐饮使用 `"restaurant"`，购买线索另带 `shopping: true`。国家范围可用 `country` 或 `countries`，城市联系可用 `city` 或 `cities`；全国通用的实用提醒在城市集合中继续展示。

运行时代码各司其职：

- `card-store.js`：加载数据、注册卡片、维护双向关系、保存和恢复即时门店；兼容旧会话中的动态卡片。
- `card-ai.js`：按卡片类型组织介绍要求和公开上下文，生成 ChatGPT 链接及复制提示词交互。
- `card-graph.js`：仅负责卡片详情、来源和关联跳转的展示。
- `china-regions.js`：省份、地级市与县级目的地关系，规范/旧路径解析、行政面包屑、三级选择器与下辖范围判定。
- `knowledge-hub.js`：国家/城市范围、分类筛选、卡片列表与地图入口；不再内嵌服务品牌或饮食内容。
- `map-provider.js`：集中创建地图与底图，小地图和完整地图复用；当前实现 OpenStreetMap / Leaflet。
- `produce.js`、`produce.css`：物产图鉴、食材筛选、季节矩阵、来源与导出、能源图表。
- `produce-supply.js`、`produce-supply.css`：同年供需矩阵、最新单项、共享分类、多指标 / 多产品对比、基年指数与逐年读数及数据与食材互跳。
- `guide.js`：欧洲国家、中国城市、物产与地图页面路由，共用目的地布局。
- `floating-map.js`、`poi.js`：随身地图、三层图层树和动态门店搜索；`map-pins.css` 统一两种地图的标记、编号与聚合样式。
- `card-manager.js`、`card-manager.css`：管理表、归属与内容搜索、筛选、分页、CSV和详情返回。
- `app.js`：可配置语言的词典搜索、收藏、详情与设备朗读。
- 对应 CSS 负责布局和分类配色；`vendor/` 保留 Leaflet 1.9.4（BSD-2-Clause）、MarkerCluster 1.5.3（MIT）及许可证。

原来分散的品牌、人物、美食、交通买票、提醒和地点构造脚本已并入数据目录，保留原有内容、来源、卡片 ID 和双向跳转。城市气候不是实时预报，物价不是实时报价；交通票种、机场区段、验证和续订仍应查卡片中的官方入口。
